# Правила работы с git

Правила обязательны для всех разработчиков и для агентов.

- Репозиторий: `waterius/jaffa_flasher`
- Интеграционная ветка (дальше `<base>`): `master`
- Работа идёт в одной рабочей копии, в каждый момент открыта одна задача и одна рабочая ветка.

## Ветки

- **Не коммитить в `master`.** Перед каждым коммитом проверять ветку командой
  `git branch --show-current`. Если это `master`, остановиться и создать рабочую ветку.
  Переключаться на `master` ради коммита нельзя.
- Рабочую ветку отводить **от свежей `master`**, а не от другой рабочей ветки. Иначе
  изменение не попадёт в `master`:
  `git checkout master && git remote update && git pull && git checkout -b <задача>`.
- Имя ветки совпадает с именем задачи: коротко, `snake_case`, строчными буквами, без пробелов и слэшей.
- Новую задачу начинать, только когда предыдущая закоммичена и отправлена в свой PR.

## Rebase и история

- История линейная: **merge-коммитов нет, только rebase.**
- **Перед каждым `git push`** делать rebase на свежую `master`:
  `git checkout master && git remote update && git pull && git checkout - && git rebase master`.
  Конфликты разрешить, при необходимости переписать сообщения коммитов.
- После rebase ветку, которая уже была отправлена, пушить только в свою ветку и только через
  `git push --force-with-lease`. Чужие ветки и `master` не перезаписывать.
- **Не использовать `git stash`.** Чтобы отложить незакоммиченные изменения, сделать временный
  коммит `git add -A && git commit -m 'wip'`, выполнить нужное, затем `git reset --soft HEAD~1`.
- Файлы добавлять в индекс явно, без `git add .`.

## PR и мерж

- PR открывать **только в `master`**: `gh pr create -R waterius/jaffa_flasher --base master`.
  Другие рабочие ветки в качестве базы PR не использовать.
- **PR мерджит только человек.** Агент не выполняет ни `gh pr merge`, ни `git merge`.
  Просьба «сделай rebase» означает `git rebase master`, а не мерж.
- **Перед каждым push проверять состояние PR:**
  `gh pr view <N> -R waterius/jaffa_flasher --json state`. Если PR в состоянии `MERGED`,
  создать новую ветку от свежей `master`, перенести коммиты через `git cherry-pick` и открыть
  новый PR. В ветку смерженного PR не пушить: изменение молча теряется, потому что ветка
  выглядит содержащей правку, CI зелёный, а PR уже закрыт.
- Не делать `--amend` коммита, уже отправленного в PR: это вдобавок обнуляет историю ревью.
- После каждого `git push` в ветку с открытым PR выводить ссылку на PR, каждый раз.
- `gh` вызывать с `-R waterius/jaffa_flasher`. Без этого `gh` берёт репозиторий из текущего
  каталога и может записать изменения не туда.

## Сообщения коммитов и описание PR

- «Что изменилось и почему» писать в сообщение коммита и описание PR, а не в комментарии
  в коде. Комментарий, понятный только в контексте текущей задачи, переносить в описание PR.
- Влияние на формат образов, команды и провода программатора описывать в PR явно.
- Документацию обновлять в том же PR, что и код.

## Проверки до push

- Тесты и сборку прогонять до PR и до push. Если тест упал, разобраться с причиной и не пушить.
- Линтер и форматтер запускать только по своим файлам и без автоисправления всего
  репозитория, чтобы чужой дифф не смешался с задачей.
- Перед коммитом проверять файлы на персональные данные.

## Секреты

- **`.env` не читать** (ни `cat`, ни `grep`, ни Read) и не редактировать. Наличие файла
  проверять через `test -f` или `ls`, переменные загружать через `source <path>/.env`.
  Если `.env` нужно поправить, дать человеку инструкцию.
- Токены, пароли, ключи и сертификаты не вписывать в код, inline-команды и `python -c`,
  брать только из `.env`. В `.gitignore` должны быть как минимум `.env*`, ключи и
  сертификаты, дампы и локальные настройки агента.

## Принуждение

Хук Claude Code `tools/claude-hooks/guard.sh` блокирует коммит в `master`/`main`,
`git stash`, `git merge`, `gh pr merge`, push ветки, не перебазированной на `origin/master`,
и чтение `.env`. Хук подключён в закоммиченном `.claude/settings.json` и включается
у каждого разработчика сам. Для работы нужен `jq`. Личные настройки агента хранить
в `.claude/settings.local.json`, этот файл в `.gitignore`.

Хук не проверяет push прямо с `master`, `--force` без `--lease`, `--amend`,
`reset --hard` и базу в `gh pr create`. Эти правила соблюдаются вручную.
