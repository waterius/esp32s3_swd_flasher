# Проверка оснастки на плате

Протокол ручной проверки change'а `swd-flash-py32f002b` (задачи 8.x в его `tasks.md`). Пункты,
которые здесь закрываются, перечислены в `MANUAL` файла `test/spec_coverage/spec_coverage_data.py`:
без живого чипа, проводов и ПК с USB их не проверить автотестом.

## Что нужно

- Оснастка: ESP32-S3 Super Mini с этой прошивкой (`pio run -e esp32s3 -t upload`), провода по
  `README.md`.
- Плата с PY32F002B, питание 3,0–3,6 В.
- Проект PlatformIO для неё с `upload_protocol = blackmagic` и `upload_port`.
- Файл 128 Б для USER OTP, слово 0 — `0xFFFFFFFF`, и такой же с замком (`0x55` по `0x1FFF0280`,
  `0xAA` по `0x1FFF0281`) — например, `test/fixtures/otp.hex` и `otp_lock.hex`.
- Для 8.2 — прошивка платы, которая сразу засыпает в Stop без `DBG_STOP`.
- gdb — из тулчейна PlatformIO: `~/.platformio/packages/toolchain-gccarmnoneeabi/bin/arm-none-eabi-gdb`.
- ПК на macOS и на Windows.

Сеанс gdb одной командой (порт подставить свой):

```sh
arm-none-eabi-gdb -nx --batch -ex "target extended-remote <порт>" -ex "monitor swdp_scan" \
  -ex "attach 1" <команды> -ex "kill"    # для чтения вместо kill — detach
```

## 8.1 Выбор чипа

- [ ] Оснастка перезаливается по своему USB дважды подряд (`pio run -e esp32s3 -t upload`).
- [ ] `chip` до выбора — `# чип не выбран: chip <имя>` и список; `chip abc` — отказ со списком.
- [ ] `chip py32f002b`, перезапуск оснастки, `chip` — `# чип: py32f002b`.
  Закрывает: `swd-flash/Чип выбирается аргументом/Выбор чипа`.

## 8.2 Подключение

- [ ] `info` 10 раз подряд; сразу после подачи питания на плату; на прошивке, которая спит в Stop.
  В ответе способ подключения, `IDCODE`, `DBG_IDCODE`, UID, HSI.
  Закрывает: `swd-flash/Подключение к спящему чипу/Прошивка платы спит`.
- [ ] То же сборкой с `-DSWD_CONNECT_AFTER_RESET_ONLY` — способ «после сброса».
- [ ] Провода SWD отключены — `monitor swdp_scan` не дольше 1 с даёт «чип не отвечает».
  Закрывает: `swd-flash/Подключение к спящему чипу/Чип не отвечает`.

## 8.3 Заливка из PlatformIO (macOS и Windows)

- [ ] `pio run -t upload` — код 0, в выводе gdb нет `MIS-MATCHED`, плата стартует новой
  прошивкой. Закрывает: `gdb-server/Заливка из PlatformIO штатно/Заливка`.
- [ ] Затем `pio device monitor` — строки `# ` с шагами и временем, `# итог: ок, <мс> мс`, после
  него лог платы. Закрывает: `swd-flash/Сообщения и время шагов/Заливка из PlatformIO`,
  `swd-flash/Плата после сеанса работает как без оснастки/Плата стартует сама`.
- [ ] Заливка, пока плата пишет лог, а монитор закрыт, — без `Protocol error`.
- [ ] Windows: порт `COMn`; `COM10` и дальше — с `\\.\`; 10 раз открыть и закрыть монитор и gdb —
  оснастка не перезагрузилась.

## 8.4 Данные вне образа и USER OTP

- [ ] `x/32xw 0x08003200` (с `detach`) до и после заливки образа без страницы 100 совпадает.
- [ ] Прошивка и файл OTP одним сеансом — `load` прошивки, `load otp.hex`, `kill`: код 0,
  `x/32xw 0x1FFF0280` совпадает с файлом. Закрывает:
  `swd-flash/Образ — только из областей чипа/Прошивка и OTP за один сеанс gdb`,
  `gdb-server/USER OTP пишется из gdb/OTP из gdb`.
- [ ] Второй раз — `# otp: совпадает`.
- [ ] Файл с замком — ошибка, код не 0, `x` до и после одинаков.
- [ ] `x/2xw 0x08000000`, затем `detach` — начальный SP и адрес старта прошивки, код 0.
  Закрывает: `gdb-server/Память и регистры для gdb/Чтение начала flash`.
- [ ] Приходит ли `EOP` после стирания и записи страницы — в design, «Результат».

## 8.5 Провал и брошенный сеанс

- [ ] Отключить SWDIO — `pio run -t upload` с кодом не 0, в мониторе «чип не отвечает».
- [ ] Прошивка с секцией за пределами 24 КБ — код не 0, плата не тронута.
- [ ] Прервать `pio run -t upload` посреди записи — плата стартует сама не позже чем через 60 с,
  ноги SWD отпущены. Закрывает: `gdb-server/Брошенный сеанс завершается/gdb убит посреди записи`.
- [ ] Перезапустить оснастку посреди сеанса — после её старта плата работает.

## 8.6 Время

- [ ] Пять заливок подряд одного образа: шаги, итог, время стирания и записи страницы против DS
  (3,5/5,0 и 1,0/1,5 мс). Закрывает: `swd-flash/Тайминги flash PY32F002B/Время стирания и записи`.

## 8.7 Лог и ноги

- [ ] Строки платы идут без `# `. Закрывает: `target-log/Лог платы в порту оснастки/Плата пишет строку`.
- [ ] `baud 9600` на плате, которая пишет на 9 600, — лог без искажений. Закрывает:
  `target-log/Скорость лога/Другая скорость`.
- [ ] `reset` — `# сброс платы`, затем первые строки платы. Закрывает:
  `target-log/Перезапуск платы командой/Перезапуск`.
- [ ] `continue` в gdb — ошибка, плата стоит до конца сеанса.
- [ ] Вне сеанса плата сама управляет ногами SWD — мультиметр показывает уровень, заданный платой.
  Закрывает: `swd-flash/Плата после сеанса работает как без оснастки/Прошивка платы использует ноги SWD`.

## Результат прогона

Дата, ОС, версия оснастки (коммит), плата, что не сработало — сюда и в design change'а,
раздел «Результат».
