# esp32s3_swd_flasher

Прошивальщик PY32F002B по SWD на ESP32-S3 Super Mini. Оснастка сама пишет чип по SWD и
отвечает gdb как отладчик Black Magic Probe, поэтому PlatformIO шьёт через неё штатной командой.
На ПК не нужны ни pyOCD, ни пак, ни драйвер программатора. USER OTP пишется из gdb.

Оснастка универсальная: она пишет присланные байты по их адресам и об изделии на плате ничего
не знает. Через один USB-порт идут и прошивка, и лог платы, и команды.

> Статус: код написан и проходит тесты на ПК; проверка на плате — `dev/board-checks.md`.

## Провода

| ESP32-S3 Super Mini | Плата с PY32F002B | Как |
|---|---|---|
| GPIO1 | SWCLK (PA2) | через резистор 100–330 Ом |
| GPIO2 | SWDIO (PB6) | через резистор 100–330 Ом |
| GPIO4 | NRST (PC0) | через резистор 100–330 Ом; оснастка тянет только к 0 |
| GPIO5 | TX лога платы | через резистор 100–330 Ом |
| GND | GND | всегда |
| 3V3 | 3V3 | **только** если у платы нет своего питания |

- Плата должна питаться от **3,0–3,6 В**. При другом питании нужен преобразователь уровней: 3,3 В
  на плате с питанием 1,8 В превышают допустимое на входе чипа, а 5 В с платы повредят ESP32-S3.
- Вне сеанса SWD оснастка ноги не держит: прошивка платы пользуется SWCLK и SWDIO как хочет.

## Сборка и заливка оснастки

```sh
pio run -e esp32s3 -t upload   # по USB самой оснастки
pio test -e native             # тесты на ПК
```

Если оснастка не перезаливается, зажать BOOT и включить её питание — она войдёт в загрузчик ESP.

Один раз выбрать чип — в мониторе порта оснастки (`pio device monitor`):

```
chip py32f002b
```

Выбор хранится в оснастке и переживает перезапуск.

## Прошивка из PlatformIO

В `platformio.ini` проекта платы:

```ini
upload_protocol = blackmagic
upload_port = COM5            ; обязателен. macOS: /dev/cu.usbmodem…; COM10 и дальше: \\.\COM10
```

Сам PlatformIO оснастку не найдёт: он ищет только настоящий Black Magic Probe.

```sh
pio run -t upload       # прошить
pio device monitor      # итог оснастки и первые строки платы
```

Перед заливкой закрыть монитор порта: порт открывает одна программа.

### USER OTP

gdb лежит в тулчейне PlatformIO: `~/.platformio/packages/toolchain-gccarmnoneeabi/bin/arm-none-eabi-gdb`
(на Windows — тот же путь в `%USERPROFILE%`, с `.exe`). Файл Intel HEX с адресами `0x1FFF0280`…
`0x1FFF02FF`:

```sh
arm-none-eabi-gdb -nx --batch -ex "target extended-remote COM5" -ex "monitor swdp_scan" \
  -ex "attach 1" -ex "load otp.hex" -ex "kill"
```

Прошивку и OTP можно залить одним сеансом — два `load` подряд. Прочитать память — `x/32xw
0x1FFF0280`, а сеанс без записи закрывать `detach`, не `kill`: `kill` без записи оснастка считает
провалом, чтобы PlatformIO увидел ошибку.

- Оснастка **никогда не ставит замок OTP** (`0xAA55` в битах 15:0 слова `0x1FFF0280`): файл с ним
  отвергается, плата не тронута.
- Совет: держите биты 15:0 слова 0 USER OTP равными `0xFFFF`. Тогда замок не возникнет даже при
  обрыве питания посреди записи.

## Команды

Строкой в мониторе порта или `monitor <команда>` в gdb:

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `chip [имя]` | выбрать чип; без имени — выбранный и поддержанные |
| `info` | подключиться и показать способ подключения, `IDCODE`, UID, HSI; перезапускает плату |
| `reset` | перезапустить плату импульсом NRST |
| `baud [скорость]` | скорость лога платы, 1 200–2 000 000; до перезапуска оснастки |
| `swdp_scan` | только в gdb: подключиться и назвать чип |

Строки оснастки начинаются с `# `, всё остальное — лог платы. Эхо оснастка не делает — в мониторе
включите `monitor_echo = yes`.

## Ограничения

- Поддержан один чип — PY32F002B.
- Байты страницы 128 Б, которых нет в образе, после записи — `0xFF`. Страницы вне образа не
  трогаются.
- Защищённые от записи страницы (WRP) оснастка не снимает: запись остановится на первой из них.
- HSI платы не 24 МГц — отказ «снимите питание платы»: NRST частоту не сбрасывает.
- Отладки нет: `continue`, шаги и точки останова gdb получит с ошибкой.
- Сеанс gdb без пакетов 60 с завершается, плата запускается.
- На macOS порт может открыть второй процесс: открытый монитор во время заливки делит байты с gdb.
- Открытие порта на скорости 1 200 перезагружает оснастку в загрузчик ESP.
- Если оснастка потеряла питание посреди сеанса, а плата питается сама, ядро платы стоит, пока на
  плате не пропадёт питание или не выполнится `info`.
