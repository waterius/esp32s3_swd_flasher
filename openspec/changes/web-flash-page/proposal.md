## Why

Через оснастку пока шьют только из PlatformIO (change `swd-flash-py32f002b`). Владелец хочет,
чтобы любой мог проверить оснастку и прошить плату из браузера, ничего не ставя
(БТ/web-flash-page/1), а заводу нужна чистая плата — полное стирание основной flash
(БТ/web-flash-page/2). Страница прошивки ещё и показывает, как говорить с оснасткой, тем, кто
будет делать страницу своего изделия.

## What Changes

- **Страница прошивки** `docs/index.html` для Chrome и Edge, публикуется на GitHub Pages:
  - выбор порта оснастки через Web Serial;
  - выбранный чип и его смена; сведения о чипе;
  - один или несколько файлов Intel HEX — разбор на странице, отказ до записи при ошибке файла,
    адресе вне карты памяти оснастки и противоречии между файлами;
  - «Прошить»: необязательное полное стирание, затем образ за один сеанс тем же протоколом gdb,
    что у PlatformIO; ход записи, итог оснастки, первые строки лога платы;
  - лог платы и команды оснастки; чтение памяти чипа с выводом в hex;
  - без внешних скриптов и сетевых запросов: файлы не покидают браузер.
- **Команда оснастки `erase`** — полное стирание основной flash, строкой и через `monitor`;
  у PY32F002B — стирание всей основной flash одной операцией, USER OTP не трогается, затем
  сверка.
- Разбор Intel HEX, кадры протокола gdb и разговор с оснасткой на странице — модули без
  браузера, с тестами на ПК (`node --test`).
- `README.md`: раздел «Прошивка из браузера».

## Capabilities

### New Capabilities

- `web-flash`: страница прошивки — подключение к оснастке, выбор чипа, файлы образа и отказы
  до записи, прошивка за один сеанс с полным стиранием по выбору, итог, лог и команды, чтение
  памяти; без установки программ и без сетевых запросов.

### Modified Capabilities

- `swd-flash` (из change'а `swd-flash-py32f002b`): полное стирание основной flash по команде
  `erase`; правило «пишутся только единицы стирания образа» получает это исключение.
- `gdb-server` (из change'а `swd-flash-py32f002b`): в списке команд — `erase`.

Обе capability ещё не перенесены в `openspec/specs/`: этот change архивируется после
`swd-flash-py32f002b`.

## Impact

- Новое: `docs/` (страница и её модули), `test/web/` (тесты на node), команда `erase` в
  прошивке оснастки. Реализация `erase` идёт после реализации `swd-flash-py32f002b`: она
  встраивается в его модули.
- Зависимости: только Web Serial в браузере. Ни фреймворков, ни сборки, ни CDN.
- Вероятно изменится:
  - **кто говорит с оснасткой** — страница прошивки, страницы изделий, позже, может быть,
    установщик прошивки оснастки. Граница — модуль разговора с оснасткой: открыть порт, выбрать
    чип, прошить файлы, прочитать память, принять лог. Интерфейс страницы над ним меняется
    свободно, страницы изделий берут модуль копией;
  - **как браузер достаёт порт** — сейчас Web Serial. Модуль разговора получает порт через
    свой маленький протокол «порт оснастки» и о Web Serial не знает.
- Сознательно не делаем:
  - WebUSB с CMSIS-DAP: правила записи жили бы в JavaScript, а оснастке нужна была бы вторая
    прошивка (design §1);
  - установку прошивки оснастки из браузера — отдельный change;
  - выпуск модулей отдельной библиотекой с версиями: страница изделия пока одна (А5).
