## Бизнес-процесс

### Как сейчас

- Плату с PY32F002B шьют с ПК. Нужны:
  - программатор ST-Link или CMSIS-DAP;
  - на ПК — Python, pyOCD, пак Puya `PY32F0xx_DFP` и драйвер программатора.
- В USER OTP pyOCD с этим паком не пишет: алгоритм для OTP в паке лежит, но к чипу не привязан.
- Если прошивка платы спит в Stop и не включает отладку во сне, чип по SWD не отвечает. Ловят
  его отдельными скриптами в первые миллисекунды после сброса, и это получается не всегда.
- Лог платы читают вторым адаптером USB-UART. Перезапускают плату кнопкой RST или снятием
  питания.

Объём: одна плата за раз. Первое производство, под которое делается оснастка, должно шить
1000 плат в день (владелец, 2026-11-11). На одном рабочем месте это 29 с на плату за 8-часовую
смену.

### Как станет

Оснастка — ESP32-S3 Super Mini (есть у владельца) и пять проводов к плате. Тип чипа ей называют
командой `chip`; сейчас поддержан один — PY32F002B. У оснастки один USB-порт: через него идут и
прошивка, и лог платы.

- **Разработчик** шьёт плату из PlatformIO штатной командой `pio run -t upload`. PlatformIO
  говорит с оснасткой как с отладчиком Black Magic Probe через gdb из своего тулчейна, ставить
  ничего не надо. Так же, командой `load` в gdb, разработчик пишет USER OTP. Лог платы он
  смотрит в мониторе того же порта и там же перезапускает плату командой `reset`.
- **Страница в браузере** (следующий change, в этом репозитории) — универсальная: выбрать файлы
  прошивки и USER OTP, прошить, увидеть итог и лог платы. Она нужна, чтобы проверить оснастку
  из браузера и чтобы любой мог попробовать прошить без программ на ПК. Говорит тем же
  протоколом (владелец, 2026-11-12).
- **Завод** шьёт со страницы своего изделия: она живёт в репозитории изделия, берёт данные для
  USER OTP откуда нужно изделию и говорит с оснасткой тем же протоколом. Оснастка о ней не знает.
- Образ присылает ПК в момент прошивки, в оснастке он не хранится. Проект платы оснастка не
  знает: она пишет присланные байты по их адресам.

### Эффект и цена

- Разработчику не нужны pyOCD, пак и драйвер программатора, и он может писать USER OTP.
- Время на плату измеряет этот change. Оценка по даташиту — около 6,5 мс на страницу 128 Б, вся
  flash PY32F002B — около 1,3 с (design §8).
- Цена оснастки и трудозатраты — открытые вопросы.

## Терминология

| Термин | Что это | Новый / уточняется |
|---|---|---|
| Оснастка | ESP32-S3 с прошивкой из этого репозитория и проводами к плате. Сама пишет образ по SWD. В отличие от программатора, ей не нужны драйвер и программа прошивки на ПК: разработчику хватает PlatformIO, заводу — браузера | новый |
| Плата | Плата с чипом, который прошивают | новый |
| Чип | Тип микроконтроллера на плате, его имя оснастке называют командой `chip`, например `py32f002b`. От чипа зависят адреса памяти, способ записи и проверка идентификатора | новый |
| Протокол gdb | Протокол, которым gdb говорит с отладчиком (GDB Remote Serial Protocol). Оснастка отвечает на нём как отладчик Black Magic Probe, поэтому PlatformIO шьёт через неё штатно | новый |
| Режим порта | Текстовый режим — лог платы и команды человека строками; режим gdb — пакеты протокола gdb. Оснастка переключает их сама | новый |
| Образ | Байты, которые ПК прислал оснастке для записи за один раз, с их адресами: у разработчика — командой `load` в gdb, из браузера — со страницы. Оснастка его не хранит | новый |
| Область памяти | Диапазон адресов чипа, куда оснастка вправе писать; у PY32F002B — основная flash и USER OTP | новый |
| Единица стирания | Наименьший кусок области, который чип стирает за раз; у PY32F002B — страница 128 Б. Оснастка стирает и пишет только единицы, где есть байты образа; байты такой единицы вне образа становятся стёртыми (`0xFF`) | новый |
| Сеанс SWD | Время от подключения оснастки к чипу до запуска платы обратно: сеанс gdb (от `monitor swdp_scan` или `attach` до `kill`, `detach`, закрытия порта или минуты тишины) или команда `info`. Вне сеанса оснастка ноги SWD не держит | новый |
| Способ подключения | Как оснастка остановила чип: под сбросом или сразу после сброса | новый |
| Итог | Последняя строка сеанса записи: `ок` или `ошибка` с причиной | новый |
| USER OTP | Страница 128 Б по адресу `0x1FFF0280` для данных пользователя: полное стирание чипа её не трогает, `0xAA55` в младших 16 битах первого слова запирает её навсегда | новый |
| Лог платы | Строки, которые прошивка платы пишет в свой UART; оснастка выводит их в свой USB-порт | новый |

## Бизнес-требования

### Добавлено

#### БТ/swd-flash-py32f002b/1. Прошивка PY32F002B без программ прошивки на ПК

Разработчик прошивает плату с PY32F002B из PlatformIO штатной командой и не ставит на ПК ни
pyOCD, ни пак, ни драйвер программатора. Оснастка сама пишет образ по SWD — в основную flash и в
USER OTP (владелец, 2026-11-11). Образ присылает gdb из PlatformIO (владелец, 2026-11-12). Из
браузера — универсальная страница этого репозитория, следующий change.

**Зачем:** разработчику не нужно настраивать свой ПК, а USER OTP наконец можно записать. По
замеру времени этого change'а владелец решает, строить ли рабочее место производства на
оснастке.

#### БТ/swd-flash-py32f002b/2. Оснастка не знает изделия

В оснастке нет сведений о конкретном изделии: ни раскладки его памяти, ни формата его данных.
Она пишет то, что есть в образе, по адресам образа, а остальную память чипа не трогает
(владелец, 2026-11-11).

**Зачем:** одна оснастка подходит для любого изделия на этом чипе. Изделие меняет свою прошивку
и раскладку памяти, не дожидаясь правки оснастки. А данные изделия вне образа (настройки,
журналы, калибровки) переживают перепрошивку.

#### БТ/swd-flash-py32f002b/3. Лог и перезапуск платы через оснастку

Человек видит лог платы в том же USB-порту, через который шьёт, и перезапускает плату командой,
не трогая её (владелец, 2026-11-11).

**Зачем:** результат прошивки виден сразу, без второго адаптера и без кнопки RST на плате.
Версия и ошибки старта видны в первых строках лога.

#### БТ/swd-flash-py32f002b/4. Чип выбирается аргументом

Человек называет оснастке тип чипа, и она прошивает только его (владелец, 2026-11-11). Сейчас
поддержан один чип — PY32F002B. Другие появятся, когда понадобятся, а порядок работы с
оснасткой для них не изменится.

**Зачем:** одну и ту же оснастку можно будет взять для изделия на другом чипе. Человек не
заливает образ одного чипа в другой: оснастка проверяет, что на плате названный чип.

## Границы

- Поддержан один чип — PY32F002B. Другие чипы (PY32F0xx, STM32 и т. п.) пока не нужны
  (владелец, 2026-11-11). Каждый — отдельный change, способ записи для них выбирается там.
- Нет страницы в браузере и полного стирания основной flash — следующий change этого
  репозитория. Страница завода для конкретного изделия — в репозитории изделия.
- Нет отладки через оснастку: продолжения, шагов, точек останова. Это отдельный change, пока не
  нужен (владелец, 2026-11-12).
- Нет проверки платы после прошивки (её функций и тока) и нет включения её питания.
- Нет своих данных для каждой платы: образ целиком присылает ПК.
- Нет option bytes, защиты чтения и полного стирания чипа.

## Открытые вопросы к бизнесу

- [ ] **Цена оснастки** (ESP32-S3 Super Mini, провода или контакты, корпус) — не блокирует.
- [ ] **Трудозатраты** — не блокирует.
- [ ] **Защита чтения.** Flash и USER OTP чипа читает любой программатор по SWD. Нужно ли
  оснастке ставить защиту чтения (option bytes) — не блокирует, отдельный change.
