> **Термины** (business.md). **Оснастка** — ESP32-S3 с этой прошивкой. **Плата** — то, что
> шьём. **Чип** — тип микроконтроллера на плате, его имя называют командой `chip`; в коде
> описание чипа — `chip` (`core/chip.h`, `chips/<имя>_desc`, `chips/<имя>_ops`). **Единица
> стирания** и **область памяти** — из описания чипа. **Образ** — байты, которые прислал gdb
> между `vFlashErase` и `vFlashDone`, в коде — `image`; что делать с каждой единицей решает
> `plan`, выполняет `write`. **Протокол gdb** — `core/rsp` (кадры) и `core/gdb` (пакеты).
> **Режим порта** — текстовый или gdb, `core/console`. **Сеанс SWD** — от подключения до
> завершения (design §5). **Лог платы** — UART платы, который оснастка пересылает в свой порт.

## 2. Описание чипа

Всё, что зависит от PY32F002B, в одном месте, без железа.

- [x] 2.1 Тип описания чипа: `core/chip.h` — области (начало, размер, единица, «читать перед
  записью», «проверять стирание», вид для gdb), идентификатор, UID, функция «решить про
  единицу» (design §6).
- [x] 2.2 Данные PY32F002B и правило OTP: `chips/py32f002b_desc.cpp`; тест на ПК — побайтовый
  замок (`0x55` по `0x1FFF0280`, `0xAA` по `0x1FFF0281`), «совпадает», «заперта и отличается»,
  «заперта и совпадает» (спека `swd-flash`, «USER OTP PY32F002B не запирается»). Тест проходит
  **до** задачи 8.4. Функция «тайминги»: пять слов информационной области → девять регистров по
  RM §4.5.2–4.5.6 (пример — значения после сброса), `HSI_FS` не `100` — отказ (сценарий «HSI не
  24 МГц»); время по DS в описании.

## 3. Образ, план, запись

Что писать, что пропустить, от чего отказаться и в каком порядке — решается и проверяется на ПК.

- [x] 3.1 Карта единиц: `core/image` и `test/test_image` на описании `py32f002b` — стирание

- [x] 3.2 План: `core/plan` и `test/test_plan` на поддельной памяти — итоговая единица с `0xFF`,

  Сценарии: «образ с замком», «OTP уже такая», «заперта и совпадает», «заперта и отличается»,
  «другой чип на плате».
- [x] 3.3 Запись: `core/write` и `test/test_write` на поддельном чипе — разблокировать, затем
  стереть, проверить стирание OTP, записать, перезарядить сторож, запереть при любом исходе;
  стоп на первом `WRPERR`, следующие единицы не тронуты; сверка и записанных, и пропущенных
  единиц; второй прогон в том же сеансе не запирает `FLASH_CR`; время шагов, наименьшее и
  наибольшее время стирания и записи, предупреждение вне даташита — по поддельным часам.
  Сценарии: «кончается посреди страницы», «данные вне образа», «сектор под защитой», «OTP не
  стёрлась», «запись не удалась».

## 4. Протокол gdb и порт

Оснастка отвечает gdb так, что PlatformIO шьёт штатно, — проверяется на ПК.

- [x] 4.1 Кадры: `core/rsp` и `test/test_rsp` — `$…#xx`, контрольная сумма, экранирование `}` в
  `vFlashWrite`, hex, числа; неверная контрольная сумма — не пакет (design §9).
- [x] 4.2 Пакеты и сеанс gdb: `core/gdb` и `test/test_gdb` на поддельной цели — таблица пакетов
  design §9; `+` до `QStartNoAckMode`; без сеанса — `E01` на `vFlash*`, `m`, `g`, `p`, `P`;
  `vKill` — `OK` только после удачной записи; `c`, `vCont;c`, `Z`, `M` — `E01`; незнакомый
  пакет — пустой ответ.
- [x] 4.3 Прогон записей из 1.6 через `core/gdb`: заливка → образ передан цели, `vKill` — `OK`;
  провал `vFlashDone` → `E01` и на `vKill`; `Load failed` → `vKill` — `E01`; неудачный
  `attach` → `vFlash*` — `E01`; два `load` → два образа; запись вне областей — цель не вызвана.
- [x] 4.4 Режимы порта и вывод: `core/console` и `test/test_console` на поддельных DTR, часах и
  командах — «кто открыл порт» (`+`/`$` — gdb, другой байт — человек, 250 мс — монитор); в
  текстовом режиме `+`/`-` вне строки пропускаются, строка по CR/LF, `$abc` — строка; выход из
  gdb по `vKill`, `D`, DTR, байту человека; вывод ждёт после `vKill`, пока порт не освободят;
  60 с тишины; буфер 4 КБ и `# пропущено`; строка `# ` с начала строки (design §9, §10). Сценарий
  «заливка, пока плата пишет лог». `pio test -e native` проходит.

## 5. SWD

Оснастка разговаривает с портом отладки чипа по двум проводам.

- [x] 5.1 Биты и транзакции: `port/swd` — запрос, ACK, данные, чётность, такты покоя, частота
  одной константой, `WAIT` до 10 мс и `ABORT 0x1F`, `FAULT` и `ABORT 0x1E` (design §3).
- [x] 5.2 Порт отладки и память: `port/dap` — вход в SWD, `CTRL/STAT`, AHB-AP с
  `CSW 0x23000052`, `TAR` на границе 1 КБ, чтение через `RDBUFF`, `STICKYERR` (design §3).
- [x] 5.3 Регистры ядра: `port/dap` — `DCRSR`/`DCRDR`, `S_REGRDY`; отметка `S_RESET_ST` при
  каждом чтении `DHCSR` (design §3).
- [x] 5.4 Остановка и NRST: `port/dap` — подключение под сбросом, иначе после сброса, флаг сборки
  `SWD_CONNECT_AFTER_RESET_ONLY`, предел 1 с, отпускание ног вне сеанса с наименьшей силой
  выхода в сеансе (design §2, §4).

## 6. Сеанс и чип

Сеанс начинается и заканчивается так, что плата после него работает как без оснастки.

- [x] 6.1 PY32F002B «подготовить» и «вернуть»: `chips/py32f002b_ops` — `DBG_IDCODE`, `DBGEN`,
  сверка через `core/plan`, `DBG_IWDG_STOP` с проверкой, `RCC_ICSCR` и слова таймингов через
  функцию «тайминги», UID; возврат: `LOCK`, `DBG_APB_FZ1` до выключения `DBGEN` (design §4,
  §5).
- [x] 6.2 Запись PY32F002B: `chips/py32f002b_ops` — «разблокировать» только при `LOCK` = 1 и
  загрузка таймингов после ключей, «запереть» с возвратом таймингов, «стереть единицу»,
  «записать единицу» со вторым рубежом OTP, «перезарядить сторож»; `BSY` с пределом 50 мс,
  `WRPERR`, `EOP`. Последовательность и тайминги сверить с `puya.c` и PR #2000 Black Magic
  Debug, расхождения — в design (design §6, §8).
- [x] 6.3 Сеанс: `port/session` — начало по `info`, `swdp_scan` и `vAttach`; завершение при
  любом исходе в порядке design §5, оба способа; отметка «идёт сеанс» в RTC-памяти и
  завершение при старте оснастки, если она осталась.
- [x] 6.4 Функции цели: `port/session` для `core/gdb` — память, регистры, запись образа через

## 8. Проверка на плате (владелец)

Нужны плата с PY32F002B (первая — Embedfire), проект PlatformIO для неё с
`upload_protocol = blackmagic` и файл 128 Б для USER OTP. Для 8.2 — прошивка, которая быстро
засыпает в Stop без `DBG_STOP`: владелец берёт свою, в репозиторий её не кладём.

- [ ] 8.1 Выбор чипа: оснастка перезаливается по своему USB дважды подряд (остаток задачи 1.2);
  `chip` до выбора — подсказка; `chip abc` — отказ со списком; `chip py32f002b` и перезапуск
  оснастки — выбор сохранился.
- [ ] 8.2 Подключение: `info` 10 раз подряд, в том числе сразу после подачи питания на плату и
  на прошивке, которая спит в Stop. Один раз — сборкой с `SWD_CONNECT_AFTER_RESET_ONLY`. Способ
  подключения, сколько раз из 10, `IDCODE`, совпадают ли регистры таймингов с заводскими — в
  design, «Результат».
- [ ] 8.3 Заливка из PlatformIO на macOS и на Windows: `pio run -t upload` — код 0, нет
  `MIS-MATCHED`; затем `pio device monitor` — строки `# ` с шагами, `# итог: ок`, после него
  первые строки платы. Заливка, пока плата пишет лог, а монитор закрыт, — без `Protocol error`.
  На Windows — порт `COMn`, если найдётся `COM10` и дальше — с `\\.\`; 10 раз открыть и закрыть
  монитор и gdb — оснастка не перезагружается. Видны ли первые строки без `reset` — в design,
  «Результат».
- [ ] 8.4 Данные вне образа и OTP: `x/32xw 0x08003200` в gdb (с `detach`) до и после заливки
  образа без страницы 100 совпадает. Прошивка и файл OTP одним сеансом — два `load`, затем
  `kill`: код 0, `x/32xw 0x1FFF0280` совпадает с файлом; второй раз — `# otp: совпадает`; файл с
  замком — ошибка, код не 0, `x` до и после одинаков. Приходит ли `EOP` — в design,
  «Результат». Только после задач 2.2 и 3.2.
- [ ] 8.5 Провал и брошенный сеанс: отключить провод SWDIO — `pio run -t upload` с кодом не 0, в
  мониторе «чип не отвечает»; прошивка с секцией за пределами 24 КБ — код не 0, плата не тронута;
  прервать `pio run -t upload` посреди записи — плата стартует сама не позже чем через 60 с;
  перезапустить оснастку посреди сеанса — после её старта плата работает.
- [ ] 8.6 Время: пять заливок подряд одного образа; шаги, итог и время стирания и записи
  страницы против DS (3,5/5,0 и 1,0/1,5 мс) — в design, «Результат».
- [ ] 8.7 Лог: строки платы без `# `; `reset` даёт её первые строки; `continue` в gdb — ошибка,
  плата стоит до конца сеанса; вне сеанса плата сама управляет ногами SWD — мультиметр
  показывает уровень, заданный платой.
