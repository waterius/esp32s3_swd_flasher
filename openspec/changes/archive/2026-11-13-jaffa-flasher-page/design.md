## Context

Страница прошивки (`docs/`, change `web-flash-page`) — обычные ES-модули без сборки и без запросов
к чужим адресам; все надписи — в объекте `T` в `app.js`; разговор с программатором —
`lib/flasher.js`, чистый код — `lib/ihex.js`, `lib/image.js`, `lib/rsp.js`; тесты — `node:test`
на поддельном программаторе `test/web/fake_flasher.mjs`. Карта памяти, которую программатор
отдаёт gdb (`qXfer:memory-map`), содержит только вид, начало, длину и блок стирания — имён
областей в ней нет. Лог платы программатор читает UART1 на 115 200 8N1, скорость меняет командой
`baud` (`Serial1.updateBaudRate`). Зачем всё это — proposal.md, Why.

Change'и `swd-flash-py32f002b` и `web-flash-page` ещё не в архиве: их спеки живут в их папках.
Архивировать по порядку: `swd-flash-py32f002b`, `web-flash-page`, этот — тогда MODIFIED
требование «Скорость лога» ложится на уже перенесённую спеку `target-log`.

## Goals / Non-Goals

**Goals:**
- страница по требованиям `specs/web-flash`: порядок блоков, спонсор, метки, галочка, терминал;
- имена областей приходят от программатора — новый чип не требует правки страницы;
- формат кадра лога — одной командой `baud`.

**Non-Goals:**
- чтение всей прошивки страницей после записи;
- сохранение настроек UART в NVS программатора;
- тёмная тема, английский язык;
- перестройка разговора с программатором (`lib/flasher.js`) сверх разбора строк областей и
  отправки `baud`.

## Decisions

### 1. Стиль Ватериуса — токены, а не копия CSS

Из `waterius/ESP8266/data/static/style.css` берутся токены: синий `#1655F5` для кнопок и
ссылок, текст `#000`/`#232323`, приглушённый `#C3BDBD`, скругление 8 px, основная кнопка
высотой 48 px, шрифт `Roboto, Helvetica, Arial, sans-serif` — системный, без загрузки (страница
не ходит на чужие адреса). Их CSS целиком не переносится: он сделан под экран телефона 360 px и
`position: fixed`. Токены — переменные `:root` в `style.css`; тёмной темы нет.

### 2. Логотип и спонсор — файлы страницы

Логотип — `docs/img/waterius-logo.svg`, копия `waterius-logo-vector.svg` из сайта Ватериуса
(`waterius.site.account/src/static/img/`), 7 КБ. Ссылка спонсора — одна константа в `app.js`,
используется в шапке и подвале; `target="_blank" rel="noopener"`. Через страницу на waterius.ru
не уходит ничего, кроме перехода по ссылке.

### 3. Схема подключения — SVG-файл

`docs/img/wiring.svg`: слева ESP32-S3 Super Mini с GPIO1, GPIO2, GPIO4, GPIO5, GND, 3V3, справа
плата с SWCLK, SWDIO, NRST, TX, GND, 3V3; на сигнальных проводах — «100–330 Ом», у 3V3 —
«только без своего питания платы». Ноги МК платы не подписываются: они зависят от платы, а
программатор и страница об изделиях не знают. Подписи — текст в SVG, без шрифтов. Отвергнуто:
схема из HTML-блоков — хуже читается и тяжелее в разметке.

### 4. Имена областей — от программатора в ответе `chip`

Решение прячет набор и имена областей чипа внутри описания чипа (`chip::Region.title`);
зависимость направлена от страницы к программатору. Команда `chip` после `# чип: <имя>` выводит
строку на каждую записываемую область (`Kind::Flash`, `unit > 0`):
`# область 0x08000000–0x08005FFF: flash, основная`, `# область 0x1FFF0280–0x1FFF02FF: USER OTP`.
`lib/flasher.js` собирает их в `state.regions = [{start, end, name, main}]` — сбрасывает при
`# чип:` и дополняет каждой строкой. Метка ставится по областям с `main === false`.

Отвергнуто:
- имена в страницу (`py32f002b → USER OTP`) — новый чип потребовал бы правки страницы;
- атрибут имени в `<memory>` карты gdb — DTD gdb его не знает, gdb его молча пропускает, но
  другой клиент может отвергнуть карту;
- отдельная команда `regions` — лишний запрос, а страница и так спрашивает `chip` при
  подключении и выборе чипа.

Чтобы метка совпадала с RM, `title` области OTP становится `USER OTP`. Сообщения программатора
меняются вместе: «USER OTP не стёрлась: 0x1FFF0280». Тексты спеки и design change'а
`swd-flash-py32f002b` и тест `test_write` правятся в том же PR.

### 5. Метки файлов — чистая функция

`lib/image.js`: `fileTags(files, regions) → [[{kind: 'region'|'overlap', text}]]` по
`parsed.ranges` файлов: область — пересечение диапазона файла с областью `main === false`;
пересечение — с диапазонами каждого файла выше по списку. Файл с ошибкой разбора меток не
получает. Байты не сравниваются: противоречие байтов ловит `buildImage` при «Прошить», как сейчас.

### 6. Галочка проверки — показ сверки программатора

`<input type="checkbox" checked disabled>` с подписью «Проверить прошивку после записи» и
пояснением «программатор сверяет каждую страницу». Логики за ней нет: сверка идёт всегда
(`writer::run`, строка `# сверка: <мс>`). Отвергнуто: чтение образа страницей после записи —
дублирует сверку, добавляет ~1 с и код чтения образа по областям.

### 7. Формат кадра лога — аргумент `baud`

`baud <скорость> [<формат>]`, формат `[5-8][NEO][12]`. Разбор — в `core/commands` (чистый код,
тесты `native`): `Host` получает `get_log`/`set_log(baud, data_bits, parity, stop_bits)` вместо
`get_baud`/`set_baud`. В `main.cpp` смена формата — `Serial1.end()` и `Serial1.begin(baud,
config, PIN_LOG_RX, -1)` с `SERIAL_<бит><чётность><стоп>`: `updateBaudRate` формат не меняет.
Ответ — `# лог: 9600 8E1`. Отвергнуто: отдельная команда `uart` — вторая команда для одной
настройки.

Страница шлёт `baud <скорость> <формат>` при смене любого из четырёх выпадающих списков и после
подключения не шлёт ничего: показывает значения по умолчанию (115 200, 8, нет, 1), пока человек
их не сменит. Заметно пользователю: после перезапуска программатора настройки возвращаются к
115 200 8N1, а страница продолжает показывать выбранные — до переподключения страницы.

### 8. «Выключить лог» — только экран

Кнопка переключает флаг страницы: пока он снят, строки платы и программатора не выводятся и не
копятся. Строки ответов на команды страницы и итог прошивки выводятся всегда — они в своих
блоках. Заметно пользователю: строки, пришедшие при выключенном логе, потеряны — включение их не
покажет.

### 9. Блокировка

Доступность — в одном месте, `render()` в `app.js`: настройки UART, кнопка лога, ввод команды —
только при `connected && !busy && !working`; «Очистить экран» обеих секций — всегда.

## Risks / Trade-offs

- [Строки `# область` разбираются по тексту] → формат закреплён спекой `swd-flash` и тестом
  `native`, поддельный программатор выводит те же строки, тест страницы на них.
- [Пересечение без сравнения байтов помечает и безвредные повторы] → так и задумано: человек
  видит, что файлы пишут одно место; запись при одинаковых байтах не отвергается.
- [Смена формата UART через `end()/begin()` теряет байты в полёте] → смена — по действию
  человека, потеря строки в этот момент допустима.

## Результат

Прогон 2026-11-13, macOS 14.5, Chrome; программатор — `master` `a27e0d2` (PR #8); плата Саши с
PY32F002B (DBG_IDCODE `0x20220064`), прошивка `waterius-node-0.0.5-node.hex`, 155 страниц.

Все пункты §7.5 `dev/board-checks-web.md` прошли:
- ссылки спонсора вверху и в подвале — waterius.ru, три метки utm, новая вкладка;
- `otp.hex` — метка «USER OTP» (после подключения, из ответа `chip`), `meas_sleep.hex` после
  `node.hex` — «пересекается с waterius-node-0.0.5-node.hex»;
- прошивка — «Итог: ок», строка `# сверка: 335 мс`; во время прошивки скорость, биты, чётность, стоп,
  кнопка лога, строка и кнопка команды недоступны;
- скорость 9600 — `# лог: 9600 8N1`, строки платы не читаются; 115200 — `# лог: 115200 8N1`, лог
  читается; на программаторе `baud 9600 7E1` — `# лог: 9600 7E1`, `9X1` — отказ с подсказкой;
- «Выключить лог» — после `reset` в терминале пусто; «Включить лог» — строки платы снова видны;
- «Очистить экран» у терминала и у памяти очищает свой блок.

Запись в USER OTP не делали: отложена владельцем.
